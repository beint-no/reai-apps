# Mirakl Marketplace Payout Reconcile

Route `/app/mirakl/`. Docs pages: `web/content/{nb,en}/web-apps/mirakl/index.md`.

One connector for every marketplace running Mirakl MMP; Elkjøp Marketplace (Elkjøp Nordic AS 911382296) is the verified Norwegian operator (elkjop-prod.mirakl.net redirects to partner.elkjopnordic.com, Mirakl footer).

## Vendor API

Current documentation (read before changing any provider call):

- https://developer.mirakl.com/content/product/mmp/rest/seller/openapi3.md (servers, Shop-API-Key security scheme)
- https://developer.mirakl.com/content/product/mmp/rest/seller/openapi3/invoicing-and-accounting/sbc11.md (SBC11)
- https://developer.mirakl.com/_bundle/content/product/mmp/rest/seller/openapi3.yaml (full spec; SBC11 examples)
- https://developer.mirakl.com/content/product/mmp/rest/seller/openapi3/invoicing-and-accounting/tl02.md (TL02, not used)

- API version: Mirakl MMP Seller REST API (paths are unversioned).
- Auth: shop API key generated by the seller in the operator's back office (user menu → user settings → API key, per third-party guides; no official Mirakl page found), sent raw in `Authorization` (no prefix).
- Host: the operator's Mirakl instance, entered by the user (https only, public host check from `assertPublicHttpsUrl`). Whether Elkjøp's API answers on `elkjop-prod.mirakl.net` or on `partner.elkjopnordic.com` is unverified.
- Endpoint: `GET /api/seller-billing-cycles?start_date=<start − 45 days>T00:00:00Z&end_date=<last day>T23:59:59Z&pay_out_state=PAID&limit=100[&shop_id=]`. Seek paging: follow `next_page_token` as `page_token` alone (Mirakl docs: other parameters are ignored with a token). At most 5 pages.
- Fields read: `id`, `date_created`, `amount_transferred_to_seller`, `currency_iso_code`, `pay_out.state/reference/transaction_date`, `payment_voucher_number`, `shop.shop_name`, `summary.total_commissions_incl_tax`, `summary.total_refund_commissions_incl_tax`, `summary.total_payable_orders_incl_tax`, `summary.total_refund_payable_orders_incl_tax` (decimal major units).
- Rate limit: SBC11 "once per day and as many times as there are pages"; one review is one to five calls.
- Subrequests: 1 to 5 Mirakl calls plus 1 ReAI bank reconciliation read.

## ReAI API

Contract: https://app.reai.no/openapi/public. Endpoints used (through `web/worker/lib/reconcile.js`):

- `GET /api/company-banks`
- `GET /api/bank-reconciliations/{bankId}?month=&include=pending_transactions`

## Accounting mapping

None booked. Payout = `amount_transferred_to_seller` on the Oslo day of `pay_out.transaction_date` (fallback `date_created`); reference = `pay_out.reference`, else `payment_voucher_number`, else cycle id; fees column = commissions net of refunded commissions incl. tax.

## Caveats

No live verification (no key). A voucher was not built because SBC11 totals carry no VAT rate split and their sign rules for refunds are only shown by example; TL02 line items have `order_tax.rate` but a rate limit of 20 calls per day recommended. Other Norwegian operators (Komplett, Clas Ohlson, XXL, Power) are not verified as Mirakl. Mirakl does not support sellers directly; questions go to the operator's seller support.

## Rules

- Use only documented endpoints, auth, parameters and fields; prefer the newest API version and server-side filtering and paging.
- Provider credentials are used for one request and never stored.
- Update this file when the API version, endpoints or caveats change.
