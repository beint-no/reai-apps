# Access Fonn

Route `/app/fonn/`. Docs pages: `web/content/{nb,en}/web-apps/fonn/index.md`.

## Vendor API

Current documentation (read before changing any provider call):

- https://api-developer.fonn.io/getting-started
- https://api-developer.fonn.io/developer/apis/fonn-api/operations?api-version=2022-04-01-preview
- https://webhooks.docs.fonn.com/

- Mode: api
- Auth: Two keys: Ocp-Apim-Subscription-Key from an approved subscription on the Fonn developer portal (api-developer.fonn.io → Profile; Fonn must activate it) and Authorization: <access token> (raw, no Bearer) generated by an org admin under ORGANIZATION → Integrations → API → Generate token.
- Hosts in code: `api-developer.fonn.io`, `ws2.fonn.io`
- Vendor status: Brreg (2026-11-28): not konkurs, not under avvikling or tvangsavvikling, no slettedato. fonn.io redirects to theaccessgroup.com product page 'Access Fonn', still sold.

## Caveats

Hours only; Fonn API has no materials or invoice basis endpoints. Base https://ws2.fonn.io/api. Time cards are per project and week: GET /projects/{projectId}/time-cards/{periodFrom}; the docs do not say whether periodFrom snaps to week start, so the code calls every 7 days from the from date and dedupes and filters by date. Projects from GET /organizations/{organizationId}/projects (page, limit, projectNumber). organizationId is optional in the UI; when empty it is discovered via GET /projectsGroups then GET /projects/{id} → data.organizationId.id. Names via /projects/{id}/members (first 100 active members), /projects/{id}/client (clientName), /projects/{id}/time-classifications/{id}. Caps: 62 days and 40 projects without a project number; 6 concurrent requests. Subrequest count is projects x weeks plus lookups, which may exceed the Workers free plan limit of 50 for larger accounts. fonn.com now redirects to The Access Group and the current site lists no email; hello@fonn.com is from Fonn's own contact page as archived 2025-11-18. fonn.no is an unrelated company. Brand orange #ff9f00 darkened to #b36b00 in the icon for white text contrast. Time cards have no id or approval status in the API, so all registered cards are fetched and refs are synthetic.

## Rules

- Use only documented endpoints, auth, parameters and fields; prefer the newest API version and server-side filtering and paging.
- Provider credentials are used for one request and never stored.
- Vouchers use `pairVoucherRows` (`web/worker/lib/voucher-rows.js`) and real VAT codes from `GET /api/vat-codes`; never VAT code 0 plus a manual 2700 line.
- Update this file when the API version, endpoints or caveats change.
