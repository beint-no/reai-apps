# ReAI Product Labels

Independent native macOS app for bulk product, price and Code 128 labels. Build with `tools/apple/build.py product-labels` from the repository root. Swift 6.4, macOS 15+, arm64; pinned Sparkle is the only external dependency.

Manual labels work offline. Browser device authorization uses product-labels and Keychain service no.reai.productlabels. Read /openapi/public before changing requests. GET /api/me chooses the single approved company; GET /api/products reads active products and variants. No catalog writes, stock changes or Shopify credentials. GET /api/product-price-lists and its prices subresource supply stored currency amounts, joined by productVariantId UUID (never numeric variantId). Use /api/me currencyCode for the base price. Never convert currencies or fall back when a selected price is missing. One price list per currency, at most four currencies on the same label. Snapshot label amounts; currency changes atomically reprice catalog batch entries. ReAI stores net prices: default to product VAT from GET /api/vat-codes, falling back to the domestic standard rate only as ReAI does. GET /api/vat-codes?usage=customer-invoice identifies whether the company uses the standard rate. Expose net and custom VAT choices for other markets; never infer a tax jurisdiction from currency. Operator reviews final prices.

Batch quantities and settings persist privately in Application Support/ReAI Product Labels/state.json. Preserve unreadable files and prevent overwriting them. Clear company data on explicit disconnect; never mix companies. No token in state or logs.

Use one renderer for preview, export and print. One label per PDF page in physical millimetres, no fit-to-page. Validate all items before submitting one bounded job (maximum 1000 labels). Keep barcode quiet zones and reject codes too dense for the label. Never truncate fields silently. Only submit to an explicitly selected installed macOS queue. Save submission status before lp; never retry prints automatically. Require confirmation and expose the previous queue status, including uncertain submissions after a restart. Temporary PDFs are private and removed after queue submission. Physical printer verification still requires matching stock and a scanner.

Keep English and Norwegian localizations complete. Inspect native UI screenshots after changes. Signed manual updates use product-labels.xml and PRODUCT_LABELS_SPARKLE_PRIVATE_KEY in apple-release. Disable update checks during print, loading and authorization, and disable app actions during the updater session. Never publish ad-hoc builds.
